## 1. 무엇을 하는 스크립트인가

현재 브랜치를 특정 base 브랜치로 **PR 했을 때 포함되는 변경 파일만** 골라, 원본 폴더 구조를
유지한 채 ZIP 으로 묶습니다. 배포 담당자에게 변경분만 전달하거나 리뷰용 스냅샷을 남기는 용도입니다.

- 비교 범위는 GitHub PR 의 **Files changed 탭과 동일**해야 한다는 것이 이 도구의 존재 이유입니다.
  이 등가성이 깨지면 도구의 가치가 사라집니다. (4.1 참조)
- 외부 의존성 없음. **git + Windows 내장 PowerShell** 만 사용합니다. node/npm 무관.
- 프로젝트 고유 결합 없음. 다른 저장소의 `scripts\` 로 복사하면 수정 없이 동작합니다.
  저장소 위치는 실행 시점의 현재 폴더에서 `git rev-parse --show-toplevel` 로 찾습니다.

**산출물**: ZIP 안에 변경 파일들 + `_changed-files.txt`(base/head/merge-base SHA·생성시각과
A/C/M/R/T/D 전체 상태 목록). 삭제(D) 파일은 ZIP 에 담을 실체가 없으므로 이 목록에만 기록됩니다.

**내용의 출처**: 파일 내용은 **작업 트리 우선**입니다. 커밋하지 않은 수정이 있으면 그 내용이
그대로 담기므로 시작 시 dirty 경고를 띄웁니다(4.6). hidden 속성 파일은 cmd 의 `copy` 가 읽지
못해 **HEAD 커밋 내용**으로 대체 추출됩니다(5.4).

## 2. 사용법

```cmd
scripts\export-diff.bat                       :: 브랜치 목록에서 번호로 선택
scripts\export-diff.bat main                  :: base 브랜치 지정
scripts\export-diff.bat origin/main out.zip   :: 출력 경로까지 지정
scripts\export-diff.bat main /v               :: 진단 정보 출력
```

| 인수 / 옵션 | 의미 |
|---|---|
| 1번째 위치 인수 | base 브랜치 (로컬명·원격 추적 ref·커밋 SHA 모두 가능) |
| 2번째 위치 인수 | 출력 ZIP 경로. 상대 경로는 **호출 시점 현재 폴더** 기준 |
| `/y` | 기존 ZIP 덮어쓰기 확인 생략 |
| `/local` | base 를 upstream 으로 자동 전환하지 않고 지정한 ref 그대로 사용 |
| `/v` | 진단 출력 (base/head SHA, upstream, ahead·behind, merge-base, 분기 시각, 상태별 목록) |
| `/h` `/?` `--help` | 도움말 |

기본 출력 경로: `%USERPROFILE%\Downloads\<저장소이름>-changed-files.zip`
(Downloads 가 없으면 `%USERPROFILE%` 로 폴백)

**종료 코드**: 정상 0 / 오류·검증 실패·**추출 누락 1개 이상** → 1.
변경 파일이 0건인 것은 정상이므로 0 입니다(삭제-전용 PR 포함 — 이때는 삭제 개수를 알려주고 종료).

출력 예:

```
  base   : origin/main   [main 의 upstream 으로 자동 전환]
  head   : feat   merge-base 364e8decb5
  PR 범위 : 17 개  =  추출 16 개 + 삭제 1 개
  복사   : 16 개 / 대상 16 개
  ZIP    : 17 개 항목  (파일 16 + 목록 1)  검증 OK
  결과   : C:\Users\USER\Downloads\clone-changed-files.zip
```

## 4. 반드시 지켜야 할 설계 결정

여기 있는 항목은 전부 **실제 버그를 겪고 나서 넣은 것**입니다. 지우거나 "간단하게" 바꾸기 전에
7장의 재발 방지 테스트를 먼저 돌려보세요.

### 4.1 base 를 upstream 으로 자동 전환한다 — 가장 중요

`export-diff.bat:176-249`

로컬 브랜치명(`main`)을 받으면 `main@{upstream}`(보통 `origin/main`)을 찾아 그 remote 를 fetch 한 뒤
**비교 기준을 upstream 으로 바꿉니다.**

**왜**: GitHub 은 PR 을 열 때마다 *현재* base 브랜치 tip 으로 merge-base 를 다시 계산합니다.
반면 로컬 `main` 은 `git pull` 하기 전까지 과거에 머뭅니다. `git fetch` 를 해도 갱신되는 것은
`origin/main` 이지 로컬 `main` 이 아닙니다. 오래된 로컬 ref 로 merge-base 를 잡으면
**이미 base 에 머지된 남의 커밋까지 diff 에 딸려 들어와 PR 보다 파일이 많아집니다.**

**건드리면**: "스크립트가 PR 보다 파일을 많이 뽑는다" 버그가 그대로 재발합니다. (5.1)

`/local` 은 의도적으로 남긴 탈출구입니다. 이때도 뒤처짐 경고는 계속 띄웁니다.
upstream 이 없는 브랜치는 전환하지 않고 "최신 여부를 확인할 수 없습니다" 경고만 냅니다.

**주의**: 전환 대상은 어디까지나 그 브랜치의 *upstream* 입니다. upstream 이 동명 브랜치가 아니면
(예: `feat` 의 upstream 이 `origin/main` 인 경우) 그쪽으로 전환되며, 요약의
`[... 의 upstream 으로 자동 전환]` 표기로 드러납니다. 의도와 다르면 `/local` 을 쓰세요.

### 4.2 압축은 `ZipFile::CreateFromDirectory` — `Compress-Archive` 금지

`export-diff.bat:363-369`

**왜**: `Compress-Archive -Path <폴더>\*` 는 와일드카드 열거라 **Hidden 속성 파일을 조용히 빠뜨립니다.**
실측 결과입니다.

```
스테이징 실제 파일 3개
Compress-Archive -Path dir\*  ->  2개   (.env 누락, 경고 없음, exit 0)
CreateFromDirectory           ->  3개
```

게다가 `Compress-Archive` 의 개별 파일 오류는 **비종료 오류**라 exit code 가 0 으로 나와
`if errorlevel 1` 에 걸리지 않습니다. 즉 "복사 3개" 라고 보고하면서 ZIP 에는 2개만 담기는
완전히 조용한 손실이 발생합니다.

**건드리면**: 개수가 어긋나는데 아무 경고도 안 나는 상태로 되돌아갑니다. (5.2)

### 4.3 개수를 3중으로 대조하고, 누락은 종료 코드로 드러낸다

한 군데서 새면 다른 데서 잡히도록 설계했습니다. 이 검증들이 앞으로의 디버깅 비용을 대신합니다.

| 대조 | 라인 | 잡아내는 것 |
|---|---|---|
| git 줄 수 ↔ 배치 집계 | 273–281 | `for /f` 파싱 손실, 배치가 다루지 못하는 경로 |
| 복사 개수 ↔ 대상 개수 | 398–399, 407–411 | 개별 파일 추출 실패. WARN + 요약의 `누락` + **exit 1** (5.5) |
| **ZIP 엔트리 수 ↔ 복사 개수** | 382–387, 403–406 | 압축 단계의 조용한 누락. 불일치면 **exit 1** |

ZIP 기대값은 `COPIED + 1` 입니다. `_changed-files.txt` 한 개가 항상 추가되기 때문입니다.
엔트리 수를 셀 때 `$_.Name -ne ''` 로 **디렉터리 엔트리를 제외**합니다 —
직접 자식 파일이 없는 중간 폴더에는 빈 디렉터리 엔트리가 생기므로 그냥 세면 항상 불일치가 납니다.

**누락(MISSING)이 1개라도 있으면 exit 1 입니다.** 예전에는 WARN 만 내고 0 으로 끝나
CI 에서 누락이 조용히 통과됐습니다. `!`/`%` 경로처럼 알려진 제약(6장)에 걸린 파일이 있어도
ZIP 은 만들어지되 종료 코드로 실패가 드러납니다.

### 4.4 `--diff-filter=ACMRT`

`export-diff.bat:265`

- `D`(삭제)는 **의도적으로 제외** — 복사할 실체가 없습니다. 대신 `_changed-files.txt` 에 남기고
  요약에 `PR 범위 = 추출 + 삭제` 로 표시해 개수 차이가 저절로 설명되게 했습니다.
  변경이 삭제뿐인 PR 은 ZIP 없이 삭제 개수와 확인 명령을 안내하고 정상 종료합니다(283–299).
- `T`(typechange)는 GitHub 이 세므로 반드시 포함해야 합니다. 예전에 빠져 있었습니다.
- 이름변경(`R`)은 `--name-only` 가 새 경로만 출력하고 GitHub 도 1개로 세므로 일치합니다.
  (`diff.renames` 기본값 true 전제)

### 4.5 `for /f` 에 `eol=|` 을 지정한다

`export-diff.bat:277, 341`

`for /f` 의 **기본 `eol` 은 세미콜론**이라 `;` 로 시작하는 경로가 집계와 복사 양쪽에서
**동시에** 빠집니다. 양쪽이 똑같이 빠지므로 경고조차 안 납니다. `|` 는 Windows 파일명에
쓸 수 없는 문자라 어떤 경로도 걸리지 않습니다. **두 루프 모두 유지해야 합니다.**

참고: `"usebackq delims= eol=|"` 처럼 `delims=` 뒤에 `eol=` 이 와도 이 환경의 cmd 는
두 옵션을 모두 인식합니다(2026-09-01, Windows 11 에서 문자열 리터럴로 실측).
`;semi.txt` 픽스처가 7-2 테스트에서 실제로 ZIP 에 들어가는 것으로도 확인됩니다.

### 4.6 복사는 디렉터리 차단 → 작업 트리 → 실패 시 `git show HEAD:` 순서

`export-diff.bat:472-489`

1. **디렉터리면 즉시 실패 처리** — 서브모듈 gitlink 는 diff 목록에 나오지만 파일이 아닙니다.
   이 차단이 없으면 `copy /y <디렉터리> <파일>` 이 디렉터리 안 파일들을 **이어 붙인 가짜 파일을
   만들어 성공해 버립니다**(개수 검증까지 통과하는 조용한 오염 — 5.3).
2. 작업 트리에 있으면 그대로 복사.
3. 복사가 실패하거나(hidden 속성 등 — 5.4) 작업 트리에 없으면(로컬에서 지웠지만 커밋에는
   있는 경우) `git show "HEAD:<path>"` 리다이렉트로 내용을 뽑습니다. 바이너리도 바이트 단위로
   무결합니다(실측: blob 해시 일치).
4. 모두 실패하면 WARN + 누락 집계 + exit 1. **조용히 건너뛰지 않는 것**이 핵심입니다.

폴백은 HEAD 내용을 담으므로 작업 트리가 dirty 면 ZIP 내용과 섞일 수 있습니다.
그래서 시작 시 dirty 경고(135–138)를 띄웁니다.

### 4.7 `chcp 65001` 과 `set /p` — 실측으로 좁혀진 제약

`export-diff.bat:3-20, 160-162, 350-351`

한글 경로를 다루려면 UTF-8 코드페이지가 필요하고, 스크립트 파일 자체도 **UTF-8(BOM 없음)** 이어야
메시지가 깨지지 않습니다. cmd 제약의 정확한 범위는 다음과 같습니다(2026-09-01 재실측):

- **파일 리다이렉트(`< 파일`)로 넘긴 입력은 `chcp` 호출 뒤 `set /p` 이 읽지 못합니다.**
  (chcp 없이 실행하면 같은 리다이렉트가 정상 동작 — `chcp` 호출 자체가 트리거)
- **파이프(`echo 1| script`)는 chcp 뒤에도 정상 동작합니다.** 예전 문서는 파이프도 안 된다고
  적었으나 재실측으로 정정합니다. 단 `echo 1 |` 처럼 파이프 앞 공백은 입력에 포함되므로,
  스크립트가 `SEL`/`ANS` 의 공백을 제거해 흡수합니다(160–162, 350–351).
- 콘솔에서 직접 타이핑하는 대화형 입력은 항상 정상입니다.

**비대화형·CI 실행에서는 base 를 인수로 넘기고 `/y` 를 쓰는 것이 여전히 가장 안전합니다.**
프롬프트 자체를 거치지 않기 때문입니다.

종료 시 코드페이지를 **원복하지 않습니다** — 949↔65001 전환이 콘솔 화면을 지워
스크립트 출력이 전부 사라지기 때문입니다(5.7). 실행 후 콘솔은 65001 로 남습니다.

## 5. 해결된 버그 기록

### 5.1 스크립트가 PR 보다 파일을 많이 뽑음 (해결)

- **증상**: base 를 로컬 `main` 으로 주면 ZIP 파일 수가 GitHub PR 보다 많음
- **원인**: base 가 원격 추적 ref 일 때만 fetch 했고, 로컬 브랜치는 stale 인 채로 merge-base 계산
- **증거**(당시 이 저장소): 로컬 `main` = `364e8de` (origin/main 보다 5커밋 뒤처짐)

  | 기준 | 결과 |
  |---|---|
  | 로컬 `main` | **5개** |
  | `origin/main` (PR 기준) | **0개** |

- **수정**: 4.1 — upstream 자동 전환
- **검증**: 수정 후 `export-diff.bat main` → 0개, PR 과 일치. 2026-09-01 재검증
  (가짜 upstream 을 둔 임시 클론에서 자동 전환 시 0개 / `/local` 시 12개+경고 재확인)

### 5.2 ZIP 에서 파일이 조용히 누락 (해결)

- **증상**: "복사 N개" 라고 하는데 ZIP 안에는 N개가 아님. 경고도 exit code 도 정상
- **원인**: `Compress-Archive -Path <폴더>\*` 가 Hidden 속성 파일을 열거에서 제외
- **증거**: 3개 중 2개만 압축됨 (4.2 표)
- **수정**: `CreateFromDirectory` 로 교체 + ZIP 엔트리 수 대조
- **검증**: 압축 직전 스테이징 파일 하나를 일부러 삭제 → `[ERROR] 불일치` + exit 1 로 검출.
  2026-09-01 재검증 완료

### 5.3 서브모듈이 "이어 붙인 가짜 파일" 로 ZIP 에 들어감 (해결, 2026-09-01)

- **증상**: 서브모듈 경로가 WARN 없이 ZIP 에 들어가는데, 내용이 서브모듈 안 파일들을
  이어 붙인 단일 파일. 복사·ZIP 개수 검증까지 전부 통과하고 exit 0 — **완전히 조용한 오염**
- **원인**: `if exist "%REL%"` 는 디렉터리에도 참이고, `copy /y <디렉터리> <파일>` 은
  디렉터리 안 파일들을 연결(concat)해 성공(errorlevel 0)함
- **증거**: 파일 2개짜리 서브모듈 커밋 → ZIP 에 두 파일 내용이 이어진 `mysub` 생성, `검증 OK`
- **수정**: `:copy_one` 진입부에서 `if exist "%REL%\" goto :copy_fail` 로 디렉터리 차단(477)
- **검증**: 같은 픽스처에서 `[WARN] 추출 실패 - 건너뜁니다: mysub` + 누락 집계 + exit 1,
  `.gitmodules` 는 정상 포함

### 5.4 hidden 속성 파일이 복사 단계에서 누락 (해결, 2026-09-01)

- **증상**: 추적 중인 hidden 파일(`attrib +h`)이 `추출 실패` WARN 과 함께 ZIP 에서 빠짐
- **원인**: cmd 의 `copy` 는 hidden 원본을 읽지 못함(실측: errorlevel 1, 대상 미생성).
  파일이 작업 트리에 "존재"하면 `git show` 폴백을 타지 않고 바로 포기하는 구조였음.
  5.2 는 ZIP 단계만 고친 것이고 복사 단계는 미해결이었음
- **수정**: 복사 실패 시 `git show HEAD:` 폴백으로 넘어가도록 `:copy_one` 재구성(4.6).
  hidden 파일은 **HEAD 커밋 내용**으로 담김
- **검증**: `.env.hidden` 픽스처가 WARN 없이 ZIP 에 포함(내용 = HEAD blob)

### 5.5 일괄 수정 (2026-09-01 검토에서 함께 해결)

| 항목 | 증상 | 수정 |
|---|---|---|
| 누락인데 exit 0 | `!`/`%` 경로 누락 시 WARN 만 내고 정상 종료 → CI 가 놓침 | 누락 ≥1 이면 [ERROR] + exit 1 (407–411) |
| 삭제-전용 PR | "추가/수정된 파일이 없습니다" 만 출력, PR 에 파일이 있다는 사실이 숨겨짐 | NDEL 을 먼저 세서 "변경이 삭제 N개뿐" + 확인 명령 안내 (283–299) |
| dirty 작업 트리 | 커밋 안 한 내용이 무경고로 ZIP 에 들어감 | 시작 시 `git status --porcelain -uno` 로 경고 (135–138) |
| WARN 안내문의 `!` 소실 | `^!` 는 지연 확장 환경에서 `!` 를 출력하지 못함 (8.2) | `^^!` 로 수정 (493) |
| worktree 브랜치 오염 | 다른 worktree 에 체크아웃된 브랜치가 `+ 이름` 그대로 목록에 들어가 선택 시 rev-parse 실패 | `:add_branch` 에서 `+ ` 접두 제거 (459–465) |
| 파이프 입력의 공백 | `echo 1 \|` 의 후행 공백이 SEL 에 포함돼 유효 번호가 거부됨 | SEL/ANS 공백 제거 (162, 351) |

### 5.7 실행이 끝나면 화면이 지워져 출력이 전부 사라짐 + 949 콘솔 파싱 오작동 (해결, 2026-09-01)

한 검토에서 두 결함이 함께 나왔습니다. 둘 다 실제 콘솔 창을 띄워 화면 버퍼를
Win32 API(`AttachConsole` + `ReadConsoleOutputCharacterW`)로 읽어 재현·검증했습니다.

**결함 A — 종료 시 출력 전멸**

- **증상**: cmd 에서 실행하면 진행 메시지·요약 등 스크립트가 찍은 echo 가 종료 직후 모두 지워짐
- **원인**: `:cleanup` 의 코드페이지 원복 `chcp %ORIGCP%`. 한국어 콘솔 기본값 949 는
  DBCS 코드페이지인데, conhost 는 **DBCS↔65001(UTF-8) 전환 시 콘솔 화면 버퍼를 지웁니다.**
  시작 시 `chcp 65001` 도 같은 이유로 화면을 지우지만 스크립트 출력은 그 *뒤*에 나오므로
  남고, 종료 시 원복이 그동안의 출력을 전부 날리는 구조였음
- **수정**: 종료 시 원복 제거(503줄은 의도를 남기는 rem 으로 대체). 콘솔이 이미
  65001 이면 시작 전환 자체를 생략
- **검증**: 949 로 시작한 실제 콘솔에서 수정 전 버전은 버퍼에 출력이 없음(전멸 재현),
  수정 후 버전은 전체 출력이 남음

**결함 B — 949 콘솔에서 배치 파싱 어긋남 (결함 A 가 가리고 있던 잠복 버그)**

- **증상**: 949 콘솔에서 실행하면 `'에' is not recognized...`, `'ISSING' is not
  recognized...` 같은 오류가 중간중간 출력되고, **ZIP 안 `_changed-files.txt` 의
  주석 한 줄이 조용히 사라짐**(실측). 수정 전 버전에도 있었지만 결함 A 의 화면 지움이
  증상을 가려 보이지 않았음
- **원인**: cmd 는 콘솔 코드페이지로 디코딩하면서 배치 파일 오프셋을 추적하는데,
  **실행 도중 chcp 로 코드페이지가 바뀌면** 한글(UTF-8 멀티바이트)이 있는 구간마다
  그 대응이 어긋나 줄 조각이 명령으로 실행되거나 정상 줄이 누락됨.
  **chcp 위치의 문제가 아님** — 최상단(한글보다 앞)으로 옮겨도 재현됨(실측).
  65001 로 시작한 콘솔은 chcp 를 건너뛰므로 항상 정상이었음
- **수정**: **자기 재실행(re-exec) 구조**로 전환(3–20줄, ASCII 전용 블록). 콘솔이 65001 이
  아니면 `chcp 65001` 후 `cmd /d /c` 로 자신을 다시 실행하고 자식의 종료 코드를 그대로
  반환. 자식 인스턴스는 **처음부터 65001 로 파싱**되므로 실행 중 코드페이지 변경이
  아예 없음. 무한 재귀는 `EXPORTDIFF_RELAUNCHED` 환경 변수로 차단 (8.7)
- **검증**: 949 콘솔 실제 창에서 `/h`·풀 실행 모두 파싱 오류 0건, manifest 전체 라인 보존,
  ZIP 검증 OK, exit 0. 재실행 경유로 공백 포함 출력 경로 인수 전달·오류 exit 1 전파·
  파이프 입력(`echo.|` → 취소) 모두 정상

**영향**: 실행 후 콘솔 코드페이지가 **65001 로 남습니다.** 되돌리려면 `chcp 949`.
949 콘솔에서는 시작 시 화면이 한 번 지워지는 것(스크립트 출력 이전)은 UTF-8 전환이
필요한 이상 피할 수 없음

## 6. 알려진 제약

전부 **조용히 빠지지 않고** WARN + 요약의 `누락` 개수로 드러나며, 누락이 있으면 **exit 1** 입니다.

| 제약 | 설명 |
|---|---|
| 경로의 `!` `%` | cmd 변수 확장 한계. 지연 확장이 `!` 를 먹습니다 |
| 서브모듈 | 파일이 아니라 gitlink 이므로 차단 → WARN + 누락 (5.3) |
| 260자 초과 경로 | 임시 스테이징 경로가 더해져 한도를 넘을 수 있음 |
| 작업 트리에 없는 LFS 파일 | `git show` 폴백이 실제 내용 대신 포인터 파일을 넣음 |

누락은 아니지만 알아둘 것:

| 동작 | 설명 |
|---|---|
| hidden 속성 파일 | ZIP 에 포함되지만 내용은 **HEAD 커밋 기준** (5.4) |
| dirty 작업 트리 | 커밋 안 한 내용이 그대로 담김. 시작 시 WARN (5.5) |
| 파일 리다이렉트 입력 | `chcp` 뒤에는 `set /p` 이 못 읽음. **파이프는 동작** (4.7). 인수+`/y` 로 회피 |
| 콘솔 코드페이지 | 실행 후 **65001 로 남음** — 원복이 화면을 지워 출력을 날리기 때문 (5.7). 되돌리려면 `chcp 949` |

## 7. 수정할 때의 테스트 레시피

배치 파일을 고친 뒤에는 **반드시 CRLF 로 저장**하고(8.1) 아래를 돌리세요.

### 7-1. 기본 동작

```cmd
scripts\export-diff.bat /h
scripts\export-diff.bat main /y          :: upstream 자동 전환 확인
scripts\export-diff.bat main /local /y   :: 전환 끄기 + 뒤처짐 경고 확인
scripts\export-diff.bat main /v /y       :: 진단 출력 확인
cd src && ..\scripts\export-diff.bat main /y    :: 하위 폴더 실행
```

### 7-2. 까다로운 경로 (한글·공백·hidden·서브모듈·삭제)

임시 클론을 만들어 테스트합니다. **작업 저장소를 더럽히지 마세요.**

```powershell
git clone <이 저장소> $env:TEMP\edtest
cd $env:TEMP\edtest
git checkout -b feat origin/main
# 한글+공백 경로, 9단계 깊이, hidden, 특수문자, 삭제 파일을 만들고 커밋
mkdir "src\기능\회원 관리\하위 폴더"; mkdir src\a\b\c\d\e\f\g
"x" > "src\기능\회원 관리\하위 폴더\깊은 파일.tsx"
"x" > src\a\b\c\d\e\f\g\lv8-deep.ts
"x" > ";semi.txt"; "x" > "a&b (c)=d.txt"
"x" > .env.hidden; attrib +h .env.hidden
git rm src\vite-env.d.ts
git add -A; git -c user.name=t -c user.email=t@t commit -m test
scripts\export-diff.bat origin/main /v /y
```

확인 포인트:

- `git diff --name-only --diff-filter=ACMRT <merge-base> HEAD` 목록과 ZIP 내용이 **파일 단위로 완전 일치**
- ZIP 안에서 `src\기능\회원 관리\...` 처럼 폴더 구조와 한글이 보존되는지, `;semi.txt` 가 들어갔는지
- `.env.hidden` 이 WARN 없이 포함되는지 (내용은 HEAD 기준)
- 요약의 `PR 범위 = 추출 + 삭제` 등식이 맞는지, `ZIP : N 개 항목 ... 검증 OK` 가 뜨는지
- `느낌표!.txt`·`pct%pct.txt` 픽스처를 추가하면: WARN + 누락 집계 + **exit 1** 이 나와야 정상
- 서브모듈을 추가하면: `[WARN] 추출 실패 ... mysub` + 누락, ZIP 에 가짜 파일이 **없어야** 함 (5.3)
- 삭제만 커밋한 브랜치에서: "변경이 삭제 N개뿐" 안내 + exit 0, ZIP 미생성

### 7-3. 검증 로직이 실제로 잡는지 (회귀 테스트)

4.3 의 대조가 살아 있는지 확인하는 테스트입니다. 스크립트 사본에 누락을 주입합니다.

```powershell
# 압축 직전에 스테이징 파일 하나를 지우도록 주입한 사본을 만들어 실행
(Get-Content scripts\export-diff.bat -Raw).Replace(
  'echo  [4/4] ZIP 생성 중...',
  "echo  [4/4] ZIP 생성 중...`r`ndel /q `"%STAGE%\root.txt`" >nul 2>&1"
) | Set-Content $env:TEMP\broken.bat
```

기대 결과: `[ERROR] 불일치 - 기대 N` 출력 + **exit code 1**.

### 7-4. 정리

테스트로 생긴 `%USERPROFILE%\Downloads\*-changed-files.zip` 과 임시 클론을 지웁니다.

## 8. cmd 배치 개발 시 주의 (이 파일에서 실제로 겪은 것)

### 8.1 CRLF 필수, UTF-8 BOM 없음

배치 파일이 **LF 만 있으면** 라벨·`goto`·괄호 블록이 오작동할 수 있습니다. 편집 도구가 LF 로
저장하는 경우가 있으니 저장 후 확인하세요.

```powershell
$p = "scripts\export-diff.bat"
$t = [IO.File]::ReadAllText($p) -replace "`r`n","`n" -replace "`n","`r`n"
[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($false)))
```

BOM 이 붙으면 첫 줄이 `﻿@echo off` 가 되어 깨집니다. 반드시 **BOM 없는 UTF-8**.

### 8.2 지연 확장과 `!`

파일 전체가 `setlocal enabledelayedexpansion` 이므로 값 안의 `!` 는 먹힙니다.
`echo` 로 리터럴 `!` 를 찍으려면 **`^^!`** 를 씁니다(`:copy_fail` 의 493줄 참고).
`^!` 로는 안 됩니다 — 파서가 캐럿을 한 번 소비한 뒤 지연 확장 단계가 남은 `!` 를 먹어
아무것도 출력되지 않습니다(실측으로 확인, 예전 문서의 `^!` 표기는 오류였음).

### 8.3 복잡한 로직은 괄호 블록 대신 `call :서브루틴`

괄호 블록 안에서는 한 줄이 통째로 파싱돼 `set` 직후 값 참조가 안 됩니다.
`:copy_one` 을 서브루틴으로 뺀 이유입니다. 서브루틴 안에서는 줄 단위로 파싱되므로
일반 `%VAR%` 확장이 정상 동작합니다.

### 8.4 PowerShell 호출은 따옴표 중첩을 피하고 파일 경유로 값을 받는다

`for /f` 안에 PowerShell 을 넣으면 따옴표·`|` 이스케이프가 금방 무너집니다.
현재 구조는 **환경 변수로 인자를 넘기고**(`$env:PSSRC`, `$env:PSDST`, `$env:PSCNT`)
**결과는 임시 파일로 받습니다**(369–372줄). 이 패턴을 유지하세요.

### 8.5 `find /c /v "" < 파일` 로 줄 수 세기

리다이렉트 형태는 헤더 없이 숫자만 출력합니다(빈 파일은 `0`). 확인 완료.

### 8.6 문자열 비교

`if not "%L%"=="%L:->=%"` 처럼 **치환 전후를 비교해 부분 문자열 포함 여부**를 판정합니다
(`findstr` 호출보다 빠르고 인코딩 영향이 없음). 큰따옴표 안에서는 `>` 가 리다이렉트로 해석되지
않으므로 캐럿 이스케이프가 필요 없습니다.

### 8.7 실행 도중 chcp 금지 — 코드페이지 전환은 자기 재실행(re-exec)으로

한글이 든 배치 파일 실행 도중 코드페이지가 바뀌면 cmd 의 줄 파싱이 어긋납니다
(5.7 결함 B — 오류 메시지 분출 + 조용한 라인 누락까지 실측). **chcp 를 파일 어디에
두든 마찬가지입니다** — 최상단(한글보다 앞) 배치도 실측으로 실패했습니다.
현재 구조(3–20줄)와 규칙:

- 콘솔이 65001 이면 곧장 `:main` 으로. chcp 자체를 호출하지 않는다
- 아니면 `chcp 65001` 후 `cmd /d /c ""%~f0" %*"` 로 자신을 재실행하고
  `exit /b %ERRORLEVEL%` 로 자식의 종료 코드를 그대로 반환한다.
  자식은 처음부터 65001 로 파싱되므로 실행 중 코드페이지 변경이 없다
- 무한 재귀 차단: 부모가 `EXPORTDIFF_RELAUNCHED=1` 을 설정하고, 자식은 이 변수가
  있으면 코드페이지와 무관하게 `:main` 으로 진입한다 (chcp 실패 시에도 루프 없음)
- 재실행 블록(3–20줄)과 그 위는 **ASCII 만** 쓴다. 한글 주석·코드는 전부 `:main` 쪽에
- 종료 시 원복하지 않는다 — 949↔65001 전환이 콘솔 화면을 지워 출력이 전부 사라진다(5.7 결함 A)
